# 项目优化计划（2026-09-29）

## 评估范围与结论

基于当前工作区源码、工作流、静态数据、现有路线图及本地测试。没有修改业务代码，没有触发采集、提交、推送或部署；未核验线上站点及远端 Actions 日志，未实测浏览器性能和布局。下面的线上链路问题属于待排查事项，不能由本地快照直接认定线上故障。

建议保留 Vue + 静态 JSON + 定时采集架构，先恢复数据可靠更新，再优化加载与维护成本。当前规模没有证据支持重写框架、引入数据库或大型状态管理库。

9 月 27 日路线图中的后台状态区分、刷新失败保留图表、首页收益风险摘要、估值样本积累提示、行情读取超时均已有实现，本计划不重复安排。

## 阶段一：排查行情更新与部署链路（P0，约 1–2 个工作日）

依据：`public/data/dashboard-source-status.json`、两份行情文件、`scripts/fetch-market.mjs`、`scripts/lib/market-data.mjs`、两套采集工作流。

工作：

1. 对照远端任务日志、数据提交和部署记录，确认最后一次成功更新的位置，区分源站连接、响应解析、文件校验、Git push 和部署故障。现有记录不足以判断根因。
2. 复用已有超时、重试、退避及底层网络错误诊断，针对实际失败修复；不盲目增加重试或自动更换行情源。
3. 检查工作流运行期间有人推送代码时的数据提交冲突。两个采集任务已有共享并发组，不再重复加锁；如需冲突恢复，保证只处理生成数据、不覆盖他人提交，并在无法安全恢复时明确失败。
4. 增加 Actions 运行摘要：各来源结果、实际数据日期、最近成功时间和失败阶段。采集失败仍保留已成功更新的数据及旧行情。
5. 比对部署后的行情文件、来源状态和统一指标，核验它们来自预期提交；必要时加构建版本标识。

验收：完整追踪一次“采集 → 数据提交 → 部署 → 页面读取”；两只证券独立报告成功或失败；失败不覆盖旧值、不推进失败回补游标、不伪造最新日期；明确当前历史仍未补齐。真实网络恢复需要外部服务配合，不以本地测试通过代替线上恢复。

## 阶段二：建立自动验证门槛（P1，约 0.5–1 个工作日）

工作：

1. 新增 PR 及主分支代码变更验证：`npm ci`、`npm test`、Python 测试、`npm run build`，使用与采集任务一致的运行时并安装所需 Python 依赖。
2. 保留当前离线测试方式，不将真实行情源可用性作为 PR 通过条件。
3. 对纯数据提交执行必要的数据格式及一致性校验；避免每次定时更新都运行无关的完整浏览器测试。
4. 为现有跳过用例明确原因和后续处理；核查依赖可变真实数据的测试，将关键固定预期放入独立 fixture。

验收：故意破坏一个校验或构建时工作流失败；正常代码通过；测试不改写仓库业务快照。分支保护规则如需启用，作为独立仓库设置变更处理。

## 阶段三：降低首屏体积（P1，约 1–2 个工作日）

依据：`src/components/ValuationTrend.vue` 全量导入 `echarts`；`src/charts/indexTrend.js` 已使用 `echarts/core` 按需注册；`ValuationAnalysis.vue` 静态导入详情组件，使相关依赖进入主入口依赖图。

工作：

1. 记录相同设备、网络条件下的首次加载 JS 传输量、请求瀑布及图表可交互时间，确认依赖实际组成。
2. 估值图改为按需注册实际使用的图表、组件和渲染器，验证与现有 K 线注册共存。
3. 将估值详情、非首屏全屏分析能力按交互或可见性加载；提供加载和失败重试状态。
4. 根据构建分析再处理其他大依赖；不以简单拆成多个同时下载的文件作为优化完成标准。

验收：首屏实际 gzip JS 传输量以降低至少 30% 为初始目标，测量后调整可行预算；图表可交互时间不退步；K 线、折线、指标切换、画线、缩放、估值弹窗及 Esc 行为保持正常。当前 536.18 kB 是主包压缩大小，不是浏览器实测首屏总传输量。

## 阶段四：共享读取状态，补关键浏览器验证（P1，约 2–3 个工作日）

依据：`Home.vue`、`LatestIndexMetrics.vue`、`ValuationMetrics.vue`、`ValuationAnalysis.vue` 分别维护读取状态；首页与全屏存在独立实例。现有组件测试有自定义 renderer 和子组件桩，不能验证真实布局及全部浏览器交互。

工作：

1. 提取页面范围的快照 composable，按数据来源和证券标识共享进行中的请求、有效快照和刷新状态，保留来源独立失败语义。
2. 首页和全屏共同使用快照，明确行情、估值与风险指标各自日期，避免刷新一个区域后另一区域仍显示未标识的旧版本。
3. 统一读取接口的超时、取消和错误映射；现有行情已有 15 秒超时，保留并复用其语义。切换证券后的迟到请求不得覆盖当前证券。
4. 增加少量浏览器端关键路径测试：证券切换、刷新失败保留旧图、重试恢复、全屏和内层弹窗 Esc 顺序、焦点返回、画线保存。
5. 实测 1440、1024、390px 视口，重点检查图表手势、整页横向溢出、按钮触达和信息密度；再决定是否缩减首页图表高度。
6. 在保留日期和来源的前提下，补价格日涨跌、指数详情/成分股直达入口。此项在数据和加载问题解决后实施。

验收：同一快照并发读取合并；刷新成功后相关视图一致；失败保留旧值及原日期；证券不串值；嵌套弹窗、键盘和窄屏操作通过真实浏览器验证。无需为了复用而一次性重写全部组件。

## 阶段五：清理维护入口（P2，约 0.5–1 个工作日）

1. 重写 README 的主运行路径，将旧 AKShare 部署说明归档。当前没有 `backend` 目录，但 `package.json` 仍有 `dev:api`、`test:api`，`render.yaml` 与 Vite 代理也保留旧架构配置；逐项确认用途后删除或标为遗留。保留 Worker API 与否需先确认是否还有使用者。
2. 把旧路线图已完成事项标记清楚，并链接本计划，避免重复开发。
3. 按官方公布情况更新 `src/data/tradingCalendar.js` 的后续年度覆盖，并记录来源和核验日期；当前只覆盖到 2026-12-31，未覆盖年份继续显示待核验，不自行推测休市日。
4. 先约定格式规范并增加必要静态检查，不进行无关的全仓格式化。是否迁移 TypeScript 留待模块复杂度和实际收益支持。

验收：新环境能按当前 README 完成静态预览、测试及构建；所有保留命令都有对应实现；日历越界行为有测试且不会误报数据正常。
