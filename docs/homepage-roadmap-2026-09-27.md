# 首页改进与后续更新计划

日期：2026-09-27。基于当前工作区代码及本地数据分析，包含已有未提交的首页调整。本文为实施建议，不表示相关功能已完成或线上状态已核验。

## 1. 项目定位与现状

建议定位为「红利低波长期观察工具」：首页帮助使用者了解价格变化、指数估值、历史风险以及数据可靠性，深入分析由全屏图表承接。

现有能力：

- Vue 3 + Vite + ECharts + Naive UI；首页读取静态 JSON，工作流负责定时采集并提交，Cloudflare 承接页面部署。
- 支持 H30269 指数及 512890 ETF；具备多周期 K 线、技术指标、画线、区间选择、全屏分析。
- 已有 PE/PB、指数股息率、十年期国债收益率、估值历史、指数资料与成分股。
- 已实现统一指标文件，包含年化收益、最大回撤、夏普以及来源、口径和异常状态。
- 有数据校验、失败保留、交易日历校验与自动测试，适合在现有架构上迭代。

主要入口：`src/views/Home.vue`、`src/components/IndexChart.vue`、`src/components/ValuationAnalysis.vue`、`src/components/LatestIndexMetrics.vue`。

## 3. 首页信息结构

桌面端建议从上到下排列：

1. **证券标题与数据状态**：证券切换、最新行情日期、重新读取按钮；说明 ETF 与标的指数的关系。正常日期差异用中性提示，真正更新失败再用警示色。
2. **四张关键卡片**：收盘价/指数点位、指数股息率、指数 PE、指数 PB。价格卡补充相较上一有效交易日的涨跌额与涨跌幅，每张卡保留数据日期。
3. **行情走势**：保留周期、范围、图形切换与放大入口；完整画线和复杂参数继续由全屏承接。提供指数详情和成分股直达入口。
4. **估值与风险概览**：桌面宽屏并排展示估值摘要与三项收益风险指标；窄屏依次排列。复用现有计算，不另写一套公式。
5. **参考信息**：十年期国债收益率、来源状态与更新安排；详细口径可折叠。

移动端关键卡片为两列，其他区域单列；图表横向手势限制在图表内部，页面不产生整体横向滚动。桌面侧栏保留本页导航，未实现模块继续收在功能规划中。

内容规则：

- ETF 行情、标的指数估值、标的指数收益风险分别标清身份。
- 样本不足 20 个不计算分位；达到阈值仍显示实际覆盖区间和样本数，不自动称为长期历史。
- 年化收益、回撤和夏普标注“已同步全部历史”，明确不代表成立以来；价格指数不含分红再投资，夏普保留 0% 无风险利率假设。
- PE/PB 的上方快照与历史摘要日期不一致时分别标明，不混用最新值计算历史排名。
- 切换 K 线周期不改变固定窗口指标的定义；后续加入可选指标窗口须单独标注。

## 4. 分阶段实施

工期为单人专注开发的粗估，按阶段验收推进，不包含等待数据源补齐和历史自然积累的时间。

### 第一阶段：数据状态与运行链路（约 2–3 个工作日）

工作：

- 统一首页 PE/PB、股息率和收益风险读取统一指标层，复用已有校验与格式化。
- 为两只证券行情、国债、估值历史提供可独立判断的采集状态；当前统一状态不能直接覆盖所有来源。
- 区分 `loading`、`ok`、采集失败保留旧值、无可用数据、状态未知；数据新鲜度单独表达。
- 行情请求增加超时处理；刷新失败保留旧图、原始日期与重试入口。
- 核验远端工作流是否执行、是否提交、是否部署以及部署快照是否一致；修复当前实际故障后再确认状态。

验收：单一来源失败不遮挡其他数据；读取旧 JSON 成功不能被写成上游更新成功；刷新不暗示触发实时采集；切换证券不会串值。

### 第二阶段：首页信息层级（约 3–4 个工作日）

工作：

- 按上述五层结构调整首页，保留当前深色风格，统一间距、字体和状态色。
- 增加价格卡涨跌信息与首页收益风险摘要。
- 将估值样本不足设计为明确的积累状态，避免出现大面积空值。
- 增加详情、成分股直达入口；减少必须先全屏再寻找信息的操作。
- 首页与全屏共享指标快照和刷新状态；优先使用 composable，无需为当前规模强行引入新状态库。

验收：1440px、1024px、390px 视口完成检查；能直接找到价格、估值、风险和数据日期；来源说明、弹窗关闭和键盘焦点可用；已有图表功能保持正常。

### 第三阶段：性能与维护（约 2–3 个工作日）

工作：

- 检查 ECharts 和详情模块的实际打包路径，按需注册图表能力、延迟加载非首屏详情。
- 测量改造前后相同环境下的首屏 JS、请求数量与图表可交互时间；不能只把大包拆成同时下载的多个包。
- 记住证券、图表周期和范围；为保存的配置增加合法性校验。
- 补首页关键交互测试，并在 PR 中自动运行现有测试与构建。
- 整理 README，区分本地静态预览、数据更新与部署流程。

验收：初始实际 JS 传输量较当前基线下降，建议以至少 30% 为优化目标；主要操作无回归；代码变更可自动获得测试和构建结果。

### 第四阶段：扩展研究能力（按数据准备程度逐项发布）

| 顺序 | 功能 | 前置条件与验收重点 |
| --- | --- | --- |
| 1 | ETF 分红记录与含分红收益 | 确认基金官方数据、除息日期与再投资规则；价格收益和含分红收益分开呈现 |
| 2 | 收益与回撤对比 | 接入可核验的基准序列；统一比较区间、分红口径和缺失处理 |
| 3 | 成分股行业分布与集中度 | 取得有效日期一致的行业分类和官方权重；缺权重时只展示数量分布 |
| 4 | 个人观察阈值 | 先提供本地偏好和页面提示；跨设备通知另行设计服务与权限 |
| 5 | 回测工具 | 先完成分红、费用、滑点和时点数据规则；现有 ZIG 信号会重绘，不能直接用回看标记充当历史可交易信号 |
| 6 | 组合配置 | 基于经过验证的多资产收益序列，再加入再平衡与风险分析 |

不建议同时展开行业、宏观、回测、组合四条产品线。下一轮扩展优先服务红利低波观察这一核心使用场景。
