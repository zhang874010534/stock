由项目维护者在 2026 年 12 月重点核查下一年度公告；若尚未公布，保留现有覆盖并继续关注。公告确认后、2027 年首个交易日前完成下面的更新。遇到交易所临时调整休市，也应按公告修订相应年度。

## 自动检查

- 本地命令：`npm run calendar:check`，按北京时间计算剩余自然日，不访问网络、不改写数据。
- 覆盖剩余超过 90 天：正常；0–90 天：警告且退出码为 0；覆盖外或结构异常：错误且退出码为 1。
- 检查完整年份边界、逐年官方来源、每年已录入休市区间、区间顺序、有效日期和重叠。不验证网页内容，不能替代人工核对公告，也不能证明所有节日均已录入。
- 复用现有两套工作日采集任务，在提交步骤之后检查，输出 Actions 注释与运行摘要。异常不阻止成功数据提交，最终任务仍报失败。配置合入远端默认分支后才随原有定时任务运行；本次没有创建额外提醒或触发远端任务。

## 更新步骤

1. 阅读上交所对应年度的正式休市公告，保存直接链接与核验日期到本文。保持补班周末休市，不把政府工作日安排当交易日。
2. 在 `annualSources` 增加年度及官方链接；逐项核对并添加 `closures`，按日期排序且不重叠，再延长 `end` 和更新 `id`。历史回补早于 2023 年时，同样需要先补官方来源及休市区间，再调整 `start`。
3. 增加该年度节假日前后、补班周末、跨年边界的固定测试。仅修改 `end` 不能通过本地检查，但填入来源和区间也不代表内容已经正确，仍需人工逐项核对。
4. 执行 `npm run calendar:check`、`npm test`、`npm run test:collectors`、`npm run build`。公式和状态测试使用固定时间，不依赖测试运行当天。
5. 在有效行情已同步后，使用完整数据刷新入口重算统一指标；确认实际区间、缺日校验和来源状态。不要通过删除失败记录、补零或放宽交易日校验消除告警。
6. 发布后核验部署文件及页面，确认没有把原先保留的指标误标为新窗口结果。

## 超出覆盖时的行为

页面 `dataFreshness` 返回“时效待核验”；收益计算遇到未覆盖的行情窗口时拒绝计算，指标生成器按原规则保留旧结果或标为不可用。日期仍在覆盖内的历史数据可以继续计算。日历到期不应阻止独立估值、股息率及国债采集。
